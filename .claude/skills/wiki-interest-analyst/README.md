# Wiki Interest Analyst — навичка для AI-агента

Навичка (Agent Skill) для аналізу інтересу до тем за переглядами статей
Wikipedia. Допомагає засновникам B2C-продуктів вирішувати **які теми
розвивати** та **якими мовами запускатися**: збирає дані Wikimedia Pageviews,
рахує тренди й **довіру до них**, будує графік і генерує звіт на одну сторінку
(PDF).

> Розраховано й перевірено на дешевій моделі **Claude Haiku 4.5**: уся змістовна
> робота — у Go-коді, агент лише обирає підкоманду й читає компактний JSON.
> Приклади у `examples/` згенеровані в режимі з цією моделлю.

## Що вміє

- Резолвити тему в назви статей **у кожній мові** (одна концепція — різні назви).
- Тягнути перегляди з Pageviews API (кеш на диску, `agent=user` → лише люди).
- Рахувати тренд (OLS-регресія, R², p-value), приріст (window growth, CAGR,
  рік-до-року), сплески й **оцінку довіри** до висновку.
- Порівнювати мови між собою.
- Генерувати графік (PNG) та звіт на одну сторінку (PDF) українською або
  англійською, з явним блоком **припущень і обмежень**.

## Швидкий старт

```bash
cd .claude/skills/wiki-interest-analyst
go build -o bin/wiki ./cmd/wiki      # потрібен Go 1.21+, мережа для залежностей

# Приклад 1: інтервальне голодування, чеською та польською
./bin/wiki brief --theme "інтервальне голодування" --langs cs,pl \
  --start 2022-01-01 --end 2024-12-31 --lang uk --out report.pdf

# Приклад 2: чи зростає інтерес до астрономії українською
./bin/wiki brief --theme "астрономія" --langs uk \
  --start 2023-01-01 --end 2024-12-31 --lang uk --out astro.pdf
```

`bin/` **не комітиться** — бінарник відтворюється з `go build`, залежності
зафіксовані в `go.mod`/`go.sum`.

## Архітектура

```
cmd/wiki/main.go          CLI-роутер: resolve | fetch | analyze | report | brief
internal/wiki/            клієнт Wikimedia (User-Agent, кеш, ретраї)
  client.go               HTTP + дисковий кеш
  pageviews.go            Pageviews API → часовий ряд, облік пропусків
  resolve.go              тема → назви статей по мовах (search + langlinks + en-hub)
internal/analyze/         тренд-метрики + модель довіри (ядро)
internal/report/          графік (gonum/plot → PNG) + звіт (fpdf → 1 стор. PDF)
  fonts/DejaVuSans.ttf     Unicode-шрифт (кирилиця) — вбудований через go:embed
references/methodology.md деталі: формули, пороги, коли не довіряти результату
examples/                 приклади викликів і згенеровані звіти
```

**Потік даних:** `theme+langs` → `resolve` (назви статей) → `fetch` (ряди,
кеш) → `analyze` (метрики + довіра) → `report` (PNG + PDF). Команда `brief`
робить усе за один виклик і друкує компактний JSON (без сирих точок, щоб не
роздувати контекст моделі); `analyze --json` зберігає повні дані для окремого
`report`.

## Як рахується довіра (стисло)

`direction` — консервативний висновок: `growing`/`declining` **лише** якщо нахил
статистично значущий і це не сплеск; інакше `stable`. `trust` (high/medium/low)
— впевненість саме в цьому висновку: поєднує якість даних (обсяг переглядів +
повнота ряду) з надійністю тренду (R², значущість, відсутність сплеску). Мала
база переглядів (< 100/період) ніколи не дає високу довіру, навіть за чистої
прямої. Повні формули — у [`references/methodology.md`](references/methodology.md).

## Тести

```bash
go test ./...
```

`internal/analyze/analyze_test.go` перевіряє поведінку на синтетичних рядах
(чисте зростання → значущий тренд + висока довіра; шум → stable; сплеск →
spike_driven; мала база → не висока довіра; пропуски → gaps).
`internal/wiki/wiki_test.go` перевіряє парсинг Pageviews, облік пропущених
періодів, кодування назв і резолвинг (через `httptest`, без мережі).
